Mockup หน้าจอ LINE 3 หน้าจอ (เวอร์ชันก่อน pivot):
1. **หน้าจอ Onboarding — เก็บ Motivation Profile** จำลอง journey step AM ของ [[20260827-01-user-journey-proactive-nudge|User Journey — Proactive Nudge ก่อนเวลาเสี่ยง]]: AI ถามเหตุผลที่ user อยากลดน้ำหนักผ่านบทสนทนาอิสระ แล้วสะท้อนกลับว่าจดจำแรงจูงใจ/เป้าหมายไว้แล้ว (FR10)
2. **หน้าจอ Onboarding — เลือกโหมดความเข้มข้น** จำลอง journey step A0: user เลือกระหว่างโหมดหักดิบ (fast-track) กับโหมดค่อยเป็นค่อยไป (gradual) ตอนเริ่มใช้งานครั้งแรก พร้อมตัวอย่างการเตือนล่วงหน้าอาการไม่พึงประสงค์ (FR8)
3. **หน้าจอ Proactive Nudge** จำลอง journey step E: AI ส่งข้อความเตือนก่อนบ่าย 2 โมงที่ user มักดื่มชาไทย พร้อมเสนอทางเลือกทดแทน (นมอัลมอนด์) แล้วแสดงผลลัพธ์เมื่อ user ตอบรับ (journey step F→G)

## องค์ประกอบในหน้าจอ mapping กลับไปยัง Requirement/Feature

### หน้าจอ 1 — Onboarding: เก็บ Motivation Profile

| องค์ประกอบในหน้าจอ | สิ่งที่สื่อถึง | อ้างอิง |
|---|---|---|
| คำถามของ AI "อะไรคือเหตุผลที่ทำให้คุณอยากลดน้ำหนัก/เปลี่ยนชีวิตในตอนนี้คะ?" | AI ถามแรงจูงใจของ user ผ่านบทสนทนาอิสระตอน onboarding (ไม่ใช่แบบฟอร์มเลือกตัวเลือก) | FR10 (F30), journey step AM |
| ข้อความตอบของ user "อยากมีชีวิตอยู่กับลูกไปนานๆ ค่ะ..." | ตัวอย่างแรงจูงใจแบบ "อยากทำเพื่อคนที่รักหรือสิ่งที่มีความหมาย" ตามที่ FR10 ระบุ | FR10 (F30) |
| ข้อความ AI ตอบกลับ "JaiFit จะจดจำไว้นะคะ ว่าเป้าหมายของคุณคือการได้อยู่กับลูกไปนานๆ" | สื่อว่าระบบสกัดและจัดกลุ่มแรงจูงใจสำเร็จ พร้อมบันทึก referenced_target ("ลูก") ไว้ใช้โยงข้อความให้กำลังใจในภายหลัง | FR10 (F31, F33) |

|---|---|---|

## สมมติฐาน/คำถามที่ต้องยืนยัน

- Mockup หน้าจอ 3 แสดงเฉพาะ **เส้นทางที่ user ทำตามคำแนะนำ** (journey step F→G) เท่านั้น ยังไม่ได้ทำ mockup ของเส้นทางปฏิเสธ (step F→H) หรือเงียบไม่ตอบสนอง (step F→I→K→L) — ควรทำเป็น mockup เพิ่มเติมถ้าต้องการสื่อสารทุกเส้นทางให้ทีมออกแบบ/พัฒนาเห็นครบ
- Mockup หน้าจอ 2 (เลือกโหมด) แสดงเฉพาะเส้นทางที่ user เลือกโหมดหักดิบเท่านั้น ยังไม่ได้ทำ mockup ของเส้นทางเลือกโหมดค่อยเป็นค่อยไป (gradual) — ถ้อยคำเตือนล่วงหน้าเป็นตัวอย่างที่แต่งขึ้นเพื่อสื่อสารหน้าตา ยังไม่ผ่านการ validate จากนักโภชนาการ/แพทย์เช่นเดียวกับตาราง phase (ดู open question 10.8 ของ spec)
- Mockup หน้าจอ 1 (motivation profile) แสดงเฉพาะเส้นทาง happy path ที่ user เล่าแรงจูงใจชัดเจนตั้งแต่ครั้งแรกเท่านั้น ยังไม่ได้ทำ mockup ของเส้นทางที่ข้อมูลกำกวมและ AI ต้องถามกลับ (FR10, F34) — การจัดกลุ่มแรงจูงใจเป็น "เพื่อคนที่รัก" ระดับ "strong" เป็นตัวอย่างที่แต่งขึ้น ยังไม่ผ่านการ validate จากนักจิตวิทยา/ผู้เชี่ยวชาญด้าน behavior change (ดู open question 10.10 ของ spec)
- ยังไม่มี mockup สำหรับหน้าจอ Reward System (การแจ้งปลดล็อก cheat meal/cheat day เมื่อ streak ครบ milestone ตาม FR9) — ควรทำเพิ่มเติมเมื่อมีการยืนยันเนื้อหา/กติกาการนับ streak ที่แน่นอน (ดู open question 10.9 ของ spec)
- ข้อความบางส่วน (คำทักทาย, อิโมจิ, ถ้อยคำที่แน่นอน เช่น "อีกสักครู่จะถึงบ่าย 2 โมงแล้วนะคะ") เป็น **ตัวอย่าง copy ที่แต่งขึ้นเพื่อสื่อสารหน้าตาเท่านั้น** ไม่ใช่ข้อความที่ยืนยันแล้วจาก spec — spec ต้นทางระบุแค่ตัวอย่างสั้น ๆ ว่า "เสนอนมอัลมอนด์" เป็นแนวทาง ไม่ใช่ script ข้อความจริง ต้องให้ copywriter/ทีมคอนเทนต์ทบทวนก่อนใช้งานจริง
- Badge phase "Onset (วันที่ 1-3)" อ้างอิงตาราง phase ในหัวข้อ 8 ของ spec ต้นทาง ซึ่งยังไม่ผ่านการ validate จากนักโภชนาการ/แพทย์ตามที่ระบุไว้ในเอกสารนั้น
- สีธีม (เขียว LINE), ไอคอน, และ layout ของกรอบมือถือเป็น default ที่เลือกเองเพื่อความสมจริง ไม่มีการกำหนด design system มาก่อนในเอกสารต้นทาง — ยังไม่ใช่ design system ที่ยืนยันแล้วของโปรเจกต์
