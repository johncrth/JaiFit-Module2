## สรุปเหตุการณ์

หลังจากอัปเดตเอกสารทั้งชุดในรอบแรกของวันนี้ (ดู [[20260828-log|log รอบแรก]]) ผู้ก่อตั้งโปรเจกต์ให้ insight เพิ่มอีก 1 เรื่องจากประสบการณ์จริง — **Motivation Profiling** จึงอัปเดตเอกสารทั้งชุดต่ออีกรอบให้สอดคล้องกัน โดยไม่รื้อโครงสร้างเดิมและไม่ซ้ำกับ insight ที่เพิ่มไปแล้วในรอบแรก (โหมดความเข้มข้น, ความหลากหลายของข้อความ, การเตือนล่วงหน้า, Reward System)

## Insight ที่นำเข้ามา

**Motivation Profiling** — เก็บข้อมูลแรงจูงใจ/สาเหตุที่ user อยากลดน้ำหนักเปลี่ยนชีวิตตั้งแต่ตอน onboarding เพราะแรงจูงใจที่ต่างกันสะท้อนความเข้มแข็งทางใจที่ต่างกัน:
- ถูกคนอื่นบังคับ/หมอสั่ง → มักอ่อนแอกว่า
- กลัวจากเหตุการณ์ภายนอก (เช่น ข่าวคนดังป่วย) → ปานกลาง
- อยากทำเพื่อคนที่รักหรือสิ่งที่มีความหมาย / ตระหนักด้วยตัวเองจากสภาพร่างกาย → มักเข้มแข็งกว่า

AI ต้องใช้ข้อมูลนี้ปรับความหนักเบาของโทนการพูดคุยและความถี่ในการให้กำลังใจ (user แรงจูงใจอ่อนกว่า → เตือน/ให้กำลังใจถี่กว่า) และสามารถโยงข้อความให้กำลังใจกลับไปหาแรงจูงใจเดิมของ user ได้ (เช่น เตือนถึงเป้าหมายอยากอยู่กับคนที่รักนานๆ)

## หมายเหตุ

- การจัดกลุ่มระดับความเข้มแข็งทางใจ 4 กลุ่ม (weaker/medium/strong/stronger) เป็นสมมติฐานจากประสบการณ์ผู้ก่อตั้งเช่นเดียวกับตาราง phase และเนื้อหาเตือนล่วงหน้าในรอบก่อน — ยังต้อง validate กับนักจิตวิทยา/ผู้เชี่ยวชาญด้าน behavior change ก่อนใช้งานจริง (open question 10.10)
- ยังไม่ยืนยันว่าควรถาม/ทบทวนแรงจูงใจของ user ซ้ำอีกหลัง onboarding หรือไม่ (open question 10.11) — Database Schema ออกแบบ `MotivationProfile` เป็น 1—* พร้อม flag `is_current` ไว้ล่วงหน้าเพื่อรองรับทั้งสองแนวทางโดยไม่ต้องรื้อ schema ภายหลัง
- Detailed Design ตั้งข้อสังเกตไว้ว่า User Journey (step E) สื่อว่า motivation profile ส่งผลต่อทั้ง nudge หลัก (B2) ไม่ใช่แค่ข้อความให้กำลังใจ (D2) แต่ API Spec ยืนยันแล้วเฉพาะการเรียก J2 ใน D2 — จุดนี้ยังเป็นช่องว่างที่ต้องตัดสินใจเพิ่มเติมก่อน implementation
