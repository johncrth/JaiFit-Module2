# Log — 2026-08-28

## สรุปเหตุการณ์

วันนี้ผู้ก่อตั้งโปรเจกต์ JaiFit (ซึ่งกำลังลดน้ำหนักแบบ low-carb ด้วยตัวเองจริง) ให้ insight ใหม่ 3 เรื่องจากประสบการณ์ตรง และขอเพิ่มฟีเจอร์ Reward System — จึงอัปเดตเอกสารทั้งชุดตั้งแต่ requirement ไปจนถึง test plan และ prototype ให้สอดคล้องกัน โดยไม่รื้อโครงสร้างเอกสารเดิม

## Insight ที่นำเข้ามา

1. **โหมดความเข้มข้นในการปรับพฤติกรรม 2 แบบ** — user เลือกได้เองตอน onboarding ระหว่าง **โหมดหักดิบ (fast-track)** ที่เข้มงวดเพื่อพา user ผ่านช่วง 7-10 วันแรกให้ได้ก่อนแล้วค่อยเสนอทางเลือกทดแทนหลังจากนั้น 1-2 สัปดาห์ กับ **โหมดค่อยเป็นค่อยไป (gradual)** ที่ให้คำแนะนำ/กำลังใจแบบช้าๆ ตลอดเส้นทางตั้งแต่วันแรก
2. **ความหลากหลายของข้อความจูงใจ** — AI ต้องไม่พูดคำแนะนำ/เมนูเดิมซ้ำๆ ติดต่อกันหลายวัน (เช่น ห้ามแนะนำเมนูเดียวกัน 7-10 วันติด) เพราะทำให้ user เบื่อและเลิกกลางทาง ต้องหมุนเวียนวิธีสื่อสาร
3. **เตือนล่วงหน้าเรื่องอาการ/สถานการณ์ไม่พึงประสงค์** — AI ต้องสื่อสารทั้งด้านบวกและเตือนล่วงหน้าถึงอาการ/สถานการณ์แย่ๆ ที่อาจเกิดขึ้น (เช่น มือสั่น มึนหัว) พร้อมวิธีรับมือ เพื่อไม่ให้ user ตกใจเมื่อเจอสถานการณ์จริง

นอกจากนี้เพิ่ม **Reward System** — ระบบปลดล็อก cheat meal/cheat day เมื่อ user ทำตามแผนต่อเนื่องถึง milestone (streak ครบ 7 วันต่อเนื่อง → ปลดล็อก cheat meal 1 มื้อที่ควบคุมได้, streak ครบ 30 วันต่อเนื่อง → ปลดล็อก cheat day เต็มวัน) เพื่อสร้างแรงจูงใจระยะยาวและให้ user มีเป้าหมายระยะสั้นที่จับต้องได้

## หมายเหตุ

- เนื้อหาที่กระทบสุขภาพ user โดยตรง (ตาราง phase, รายการอาการเตือนล่วงหน้า) ยังต้อง validate กับนักโภชนาการ/แพทย์เช่นเดิม — ไม่มีการเปลี่ยนแปลงในหลักการนี้
- กติกาการนับ/รีเซ็ต streak ของ Reward System (open question 10.9) และความถี่ที่อนุญาตให้เปลี่ยนโหมด (open question 10.6) ยังไม่ยืนยันค่าจริง ต้องตัดสินใจก่อนเข้าสู่ implementation
