# Log — 2026-08-28 (รอบ 3 — Pivot ช่องทางจาก LINE OA เป็น Web App)

## สรุปเหตุการณ์

หลังจากอัปเดตเอกสารด้วย insight ใหม่ 2 รอบก่อนหน้าในวันนี้ (ดู [[20260828-log|log รอบแรก]], [[20260828-02-log|log รอบ 2]]) โปรเจกต์ JaiFit ได้รับ**ทิศทางสำคัญใหม่**: ต้องปรับจาก LINE Official Account bot เป็น **Web App Full-Stack** (Frontend + Backend + Database) ที่ deploy ใช้งานได้จริง

## เหตุผลของการปรับทิศทาง

เป็นข้อกำหนดของ**หลักสูตร ADT-RAISE** ที่ผู้จัดทำกำลังเรียนอยู่:
- ผลงานปลายทางของหลักสูตรกำหนดเป็น **"Web App Full-Stack + AI, Deploy จริง"**
- **Module 2** ของหลักสูตรสอน Full-Stack ด้วย **Node.js/Git** เป็นหลัก

**หลักการสำคัญ:** แนวคิดฟีเจอร์และ data flow เดิมที่ออกแบบไว้ทั้งหมด (เก็บพฤติกรรมการกิน, proactive nudge, phase tracking, โหมดความเข้มข้น, message variety, downside warning, Reward System, Motivation Profiling) **ยังคงไว้เหมือนเดิมทุกจุด ไม่มีการเปลี่ยนแนวคิดฟีเจอร์แม้แต่ข้อเดียว** — สิ่งที่เปลี่ยนคือ**ช่องทางที่ user ใช้งาน** จากแชท LINE เป็นหน้าเว็บ และ**ช่องทางแจ้งเตือนเชิงรุก** จาก LINE push message เป็น Web Push Notification/Email

## Technology Stack ที่ตัดสินใจ (พร้อมเหตุผล)

| ส่วน | เทคโนโลยี | เหตุผล |
|---|---|---|
| Backend | **Node.js + Express** | ตามข้อกำหนดหลักสูตรที่สอน Node.js เป็นหลักใน Module 2 |
| Frontend | **React (Vite)** | ระบบนิเวศใหญ่ที่สุด มักถูกสอนคู่กับ Node.js ใน bootcamp/หลักสูตร full-stack ทั่วไป เรียนรู้ได้เร็วด้วย Vite (setup เบากว่า Create React App) และ component-based UI เหมาะกับหน้าจอที่มีหลาย state (chat, wizard, dashboard) ของ JaiFit |
| Database | **PostgreSQL** | ข้อมูลของ JaiFit เป็นแบบ relational ชัดเจนอยู่แล้ว (User, BehaviorPattern, NudgeLog, PhaseDefinition, StreakRecord, MotivationProfile ฯลฯ ที่มี ER diagram/FK ชัดเจนในเอกสารเดิม) PostgreSQL จึงตรงกับโมเดลข้อมูลที่ออกแบบไว้โดยตรง และมี managed hosting ฟรี/ราคาถูกหลายเจ้าที่ deploy ง่ายสำหรับ MVP ระดับหลักสูตร (เช่น Supabase, Neon, Railway) |
| AI | **Claude API (Anthropic)** | ตามที่ระบุไว้ในโจทย์ตั้งแต่ต้น สำหรับ NLU สกัด behavior pattern/motivation profile และ generate เนื้อหาที่หลากหลาย |
| Notification | **Web Push Notification (หลัก) + Email (สำรอง)** | Web Push ให้ประสบการณ์ใกล้เคียง LINE push เดิมที่สุด (มาถึงแบบเรียลไทม์แม้ปิดแท็บ) ผ่าน Browser Push API + Service Worker, Email เป็น fallback เมื่อ user ไม่อนุญาต/ไม่รองรับ |
| Authentication | **Email + Password** | ง่ายและเรียนรู้ได้เร็วที่สุดสำหรับ MVP ระดับหลักสูตร ไม่ต้องพึ่ง third-party OAuth |

## หมายเหตุ

- เอกสารเดิมที่ออกแบบไว้ก่อน pivot (mockup LINE) ไม่ได้ถูกลบ แต่ย้ายไปเก็บที่ `docs/00-archived/` ตามหลักการของโปรเจกต์ที่ "ไม่ลบเอกสาร ย้ายไปเก็บไว้แทน"
- รายละเอียดเชิงเทคนิคบางส่วนยังเป็น open question ที่ต้องตัดสินใจก่อน implementation จริง: นโยบาย fallback เมื่อ user ไม่อนุญาต Web Push (10.12) และกลไก authentication/session ที่แน่นอน (session cookie vs JWT vs third-party auth) (10.13)
- Hosting/deploy target ที่แนะนำ (ยังไม่ใช่การตัดสินใจบังคับ): Frontend บน Vercel/Netlify, Backend บน Render/Railway, PostgreSQL แบบ managed (Supabase/Neon/Railway) — เลือกได้ตามความสะดวกของทีมพัฒนาตอน implement จริง
