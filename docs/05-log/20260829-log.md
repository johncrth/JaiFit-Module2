# Log — 2026-08-29 (รอบ 4 — ปิด Open Questions)

## สรุปเหตุการณ์

ผู้จัดทำยืนยันการตัดสินใจปิด **Open Questions 12 จาก 13 ข้อ** ในหัวข้อ 10 ของ [[../01-requirements/01-spec/20260827-01-jaifit-ai-coach-metabolic-transition|Requirement Spec]] (เหลือเฉพาะ **10.5** — target metric ตัวเลขจริง ที่ยังรอข้อมูล baseline เพิ่มเติม) พร้อมเพิ่มฟีเจอร์ใหม่ 2 ตัวจากการตัดสินใจเรื่องตาราง phase (FR12 — Chronic Condition Screening, FR13 — Adaptive Symptom Easing) และบันทึกหมายเหตุการพิจารณา Native Mobile App ในอนาคต

|---|---|---|

## เหตุผลเบื้องหลังการตัดสินใจที่มีผลกระทบมากที่สุด

- **10.4 (ตาราง Phase + กลุ่มผู้ใช้):** เดิมเป็นความเสี่ยงสูงสุดของโปรเจกต์เพราะกระทบสุขภาพ user โดยตรง การแยกกลุ่มผู้ใช้ตามโรคประจำตัว (FR12) และกลไกผ่อนปรนตามอาการ (FR13) ช่วยลดความเสี่ยงนี้ในระดับ MVP โดยไม่ต้องรอ validate จากผู้เชี่ยวชาญให้เสร็จก่อนเริ่ม implement — หลักการคือ "ปลอดภัยไว้ก่อน" (fail-safe) เมื่อพบสัญญาณอาการรุนแรง แทนที่จะหักดิบต่อตามแผนเดิม
- **10.9 (Grace Day):** เลือกแนวทางผ่อนปรนที่สุดในบรรดา 3 แนวทางที่เสนอ เพราะสอดคล้องกับหลักการ non-judgmental ที่ยึดถือมาตั้งแต่ FR4 — ป้องกันไม่ให้ user รู้สึกว่าพลาดครั้งเดียวแล้วเสียทุกอย่าง ซึ่งเป็นสาเหตุหนึ่งของการล้มเลิกกลางทาง
- **10.11 (ทบทวนแรงจูงใจตามกลุ่ม):** เชื่อมโยงกับ 10.10 — user ที่มีแรงจูงใจเข้มแข็งอยู่แล้วไม่จำเป็นต้องถูกถามซ้ำให้เสียเวลา ส่วนกลุ่มอ่อนกว่าต้องการการตอกย้ำเป็นระยะ จังหวะหลัง reward ถูกเลือกเพราะเป็นช่วงที่ user รู้สึกดีกับตัวเองอยู่แล้ว เหมาะกับการต่อยอดบทสนทนาเชิงบวก
- **10.13 (JWT + Google Sign-In/Email-Password):** JWT สอดคล้องกับสถาปัตยกรรม React SPA + Node.js API ที่แยกกันชัดเจนอยู่แล้ว ส่วนการเพิ่ม Google Sign-In เป็นทางเลือกที่สองช่วยลด friction ตอนสมัครสมาชิกโดยไม่ต้องพึ่ง third-party auth service เต็มรูปแบบ (เช่น Supabase/Firebase Auth) ที่จะเพิ่ม dependency นอกเหนือ stack หลักที่เลือกไว้แล้ว

## หมายเหตุ

- 10.5 (target metric ตัวเลขจริง) ยังคงเปิดอยู่ตามที่ผู้จัดทำยืนยัน — ไม่กระทบ implementation ของฟีเจอร์ใดในรอบนี้ เพราะเป็นแค่ตัวเลข target สำหรับวัดผลใน [[../01-requirements/02-plan/index|02-plan]]
- รายละเอียดเชิง threshold ตัวเลขจริงหลายจุด (เช่น เพดาน nudge/วันต่อ phase, จำนวนครั้ง "ไม่ตอบสนองต่อเนื่อง", เกณฑ์ `severity_level = severe` ของ Adaptive Symptom Easing) ยังไม่ได้กำหนดเป็นตัวเลขในรอบนี้ — เป็นรายละเอียดเชิง implementation ที่ทีมเทคนิคต้องกำหนดต่อ ไม่ใช่ open question เชิงการตัดสินใจเชิงหลักการอีกต่อไป
- เนื้อหาตาราง Phase, WarningContent, และเกณฑ์การจัดกลุ่มความเข้มแข็งทางใจ ยังคงเป็นสมมติฐานที่ยังไม่ผ่านการ validate จากผู้เชี่ยวชาญ (นักโภชนาการ/แพทย์/นักจิตวิทยา) ตามเดิม — การปิด open question รอบนี้เป็นการยืนยัน "แนวทาง" ว่าจะใช้สมมติฐานไปก่อนใน MVP ไม่ใช่การยืนยันว่าเนื้อหาถูกต้องแล้ว
